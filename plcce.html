PLC Tank Process — Sequential IF–THEN Logic

Press Start. The PLC steps through the process by checking its rules on every scan: fill → mix → drain → ready.

What question does this page answer?

How can a PLC run a whole fill → mix → drain sequence just by checking a few simple IF–THEN rules over and over?

Sub-questions

    By the end you can…

    • describe one scan as READ inputs → SOLVE every rule → UPDATE outputs;
    • name the condition that ends each step, and the rule that checks it;
    • explain why a rule whose IF is TRUE can still do nothing (the step memory);
    • read a timer as elapsed (ET), preset (PT), remaining and done (Q);
    • find the scan in a timing diagram where each output changes, and say which rule changed it.

    How to use this page (about 15–20 min)

    1. Press ▶ Start at 2× and watch one full cycle (about 20 s). Follow What just happened?
    2. Tick Pause & predict and press Start again: answer before each step change, then the page stops on the change so you can check your prediction.
    3. Use ⏸ Pause and Step one scan to read each rule’s “This scan” line in Control rules, scan by scan.
    4. Press Reset in the middle of a cycle and read what it did.
    5. Read the timing diagram and the cycle summary, then do the self-check.
    What you should already know (three one-line refreshers)
    • Inputs and outputs: buttons and sensors are inputs (the PLC reads them); valves and motors are outputs (the PLC writes them).
    • 1 and 0: 1 = ON = TRUE, 0 = OFF = FALSE.
    • AND: “X AND Y” is TRUE only when X and Y are both TRUE.

    Control rules (checked every scan)

    On this scan, what does each rule read, is its IF TRUE or FALSE, and what does the PLC do with it?

    Each card shows the rule (the program, never changes) and its This scan line (live values). ACTIVE = this rule’s THEN is what the outputs are doing now (the other cards say “not active”) · WATCHED = the condition the current step is waiting for · FIRED = the IF became TRUE and the step changed on this scan · ENDED = the PLC just left this rule’s step · not its step = nothing to do now.      STEP_FILL                               PA_CMD

      Rung 1: STEP_FILL is ON while (Start is pressed OR STEP_FILL was already ON) AND the level switch does NOT read full. The parallel STEP_FILL contact is how the PLC remembers the short Start press. Rung 2: valve A is commanded open while STEP_FILL is ON (PB_CMD gets the same rung). In the full program you will also add a condition so that Start only works from IDLE.
