What question does this exercise answer?

How do a holding contact and three healthy-state permissives decide, scan by scan, whether the PLC commands the conveyor motor ON?

Each task below answers one part of this question. A part is marked Answered once you resolve its task (correct answer, or three attempts used).

Sub-questions, one per task

    By the end you can…
    • Trace one PLC scan for this conveyor as READ inputs → SOLVE Rungs 1, 2, 3 → UPDATE outputs.
    • Predict the MOTOR_RUN command for a start, a release, a stop, an open guard, an overload trip and an overload reset.
    • Point to the instruction on a rung that writes a bit, and to the ones that only test bits.
    • Choose a coil type for a motor command and justify the choice.
    • Separate the cause of a stop from its downstream symptoms.
    • Explain why MOTOR_RUN = 1 is a command, not proof that the motor turns.

    What you should already know (one-line refreshers)
    • Bit: a Boolean tag holds 0 or 1.
    • N.O. contact: a software test that is TRUE when its bit is 1.
    • Series and parallel: instructions in series must all be TRUE (AND); parallel branches need at least one TRUE branch (OR).
    • Scan cycle: the PLC reads all inputs, solves the rungs from top to bottom, then updates the outputs, and repeats.

    Practice environment

    Conveyor holding circuit and permissives

    This section answers: What is this exercise about, and which layers (device, bit, instruction, command) must I keep apart?

    Apply an IF–THEN rule as PLC data and ladder instructions. The exercise separates the physical buttons, stored bits, contact tests, rung results, coil writes and output commands.

    Physical inputA push button or field device changes an electrical input signal.
    Contact instructionReads a stored Boolean tag and returns TRUE or FALSE.
    Ordinary coilWrites the current rung result to a Boolean tag on every scan.
    Output commandMOTOR_RUN = 1 commands the output; it does not prove the motor is rotating.
    Control-logic training boundary

    This exercise teaches ordinary PLC logic and positive healthy-state tags. Real emergency-stop and guard functions require a properly engineered safety circuit, safety relay or safety PLC. Do not treat this rung as a complete machine-safety design.

    Big picture: from push button to conveyor motor (8 steps)

    This section answers: How does a physical button press become a motor command in this conveyor, and where does each tag live? Follow the steps 1 → 8.

    1. Field deviceMomentary Start PB (N.O.). Stop PB is wired N.C., so its circuit is closed until pressed. Guard switch and OL relay are closed while healthy.
    2. Input moduleEach 24 V input channel becomes 1 (voltage present) or 0 (no voltage).
    3. Input image (READ)At the start of every scan the PLC copies the channels into START_PB, STOP_OK, GUARD_OK, OL_OK.
    4. Instructions (SOLVE)N.O. contacts on Rung 1 test those bits and the internal RUN_REQ bit; series = AND, parallel = OR.
    5. Rung resultTRUE only if a complete TRUE path joins the left rail to the right-hand instruction.
    6. Data writtenRUN_REQ (internal memory) on Rung 1, then MOTOR_RUN on Rung 2, then RUN_LAMP on Rung 3 — in that order, in the same scan.
    7. Output image → module (UPDATE)After all rungs are solved, MOTOR_RUN and RUN_LAMP are sent to the output channels.
    8. ActuatorThe motor contactor coil pulls in and the conveyor motor starts; the running lamp lights.

    Two meanings of “normally”. The physical Stop button is normally closed (N.C.), so STOP_OK = 1 while nobody presses it. The software contact that tests STOP_OK is normally open (N.O.): it is TRUE while the bit is 1. A broken wire also gives 0, the same value as a pressed Stop button; that is why the exercise uses positive healthy-state tags.

    Command, not proof. MOTOR_RUN = 1 only commands the output. Proving that the motor turns needs a feedback input, such as a contactor auxiliary contact or a speed sensor, which this exercise does not have.

    What the PLC does during the current scan

    This section answers: In which order does the PLC read the inputs, solve the three rungs and update the outputs on this scan?

    The holding contact does not receive a special signal from the coil. The ordinary coil writes RUN_REQ; the contact reads the same stored bit when the rung is evaluated again.

    Every scan the PLC first READS all inputs into the input image, then SOLVES Rung 1, Rung 2 and Rung 3 in order using stored bit values, then UPDATES the output modules.

    Green ladder lines show a TRUE logical path. They do not represent real water or electrical current flowing through the software diagram. Like online monitoring, the ladder is coloured with the bit values stored at the end of this scan; the scan replay (shown after you answer) lists what each contact read during the scan.
